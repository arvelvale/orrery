# 00 · 项目定位

## 一句话

Orrery 是个人桌面驾驶舱：把多个 agent harness 的**会话**与**模型路由**收进一个界面，先服务自己每天用得爽，再考虑开源影响力。

## 动机

并行使用 Claude Code、Kimi Code、DSH（DeepSeek）、Codex 时的真实摩擦：

1. **模型切换分散**——每个 harness 各写 env / config / settings，切换成本高且易漏。
2. **会话互不相通**——本地 JSONL / 会话目录格式不一，无法统一搜索、对比、恢复。
3. **态势不可见**——谁在跑、谁报错、谁空闲，只能挨个开终端看。

## 价值排序（重要）

| 优先级 | 能力 | 理由 |
|---:|---|---|
| P0 | 跨 harness 会话中枢 | 目前没有像样的开源赢家；实现边界清晰 |
| P0 | 本地模型代理 + 路由 | 痛点真实；用「一个 endpoint」消化各家差异 |
| P1 | 多窗格终端编排 | 有哇点，但维护成本高，放到第二阶段 |
| P2 | 开源运营（文档站、插件生态） | 自用稳定后再谈 |

## 不做范围（MVP 明确砍掉）

- 不做「全能壳」重新实现 agent 逻辑（不 fork 各家 CLI）
- 不做云端同步 / 多用户 / 团队协作
- 不做插件市场
- 不在原型阶段伪造真实网络请求

## 成功标准

**自用（当前）**

- 打开应用 3 秒内看清：代理是否在线、各 harness 运行/错误状态、最近会话
- 一次点击完成：某 harness 默认模型切换（写入本地配置）
- 搜索会话能命中标题 / 项目路径 / 模型名

**开源（以后）**

- 外人 clone 后能接上至少 2 个 harness 的真实会话目录
- 模型代理可用 OpenAI-compatible 端点给任意 harness 供电

## 命名

- 产品名：Orrery
- 叙事：驾驶舱 / 航行情报条 / 告示牌灯（见 DESIGN.md），仅作结构隐喻，不堆航空装饰
